# Ninjago: Total War - changelog and roadmap

A Total War-style LEGO Ninjago army battler, built for a seven-year-old. This file tracks what each
version added. Per-version testing steps live in [`docs/TESTING.md`](TESTING.md).

> **Important:** the project is developed on a Linux host with no engine installed. **v0.1 through
> v0.9 are authored but not yet compiled or playtested.** The first Windows build (UE 5.7.4) is the
> real acceptance gate. Pure-logic systems are backed by headless automation tests and were
> additionally checked with standalone math mirrors; the stateful/integration systems (marked below)
> were verified by reasoning and traces, not tests.

## Branch model

Each version is a cumulative branch off the previous one, so a later branch contains everything
before it. `v0.9` is the fullest build.

```
main -> v0.1 -> v0.2 -> v0.3 -> v0.4 -> v0.5 -> v0.6 -> v0.7 -> v0.8 -> v0.9
```

## v0.1 - Core game

The whole v0.1 scope, built in seven milestones (M1-M7).

- **Project + data**: UE 5.7 C++ project (module `Ninjago`), four DataTables generated by `build.py`
  (209 units, 17 factions, 16 archetypes, 44 abilities), `UNinjagoSettings` for all tuning constants.
- **Combat resolver**: pure hit-chance and damage with the `max(1, ...)` floor so armour never makes
  a unit unkillable. Headless tests.
- **Formation**: pure symmetric block geometry.
- **Rendering**: no skeletal meshes. Each unit is six `HierarchicalInstancedStaticMeshComponent`s
  (one per minifig part), animated by writing rigid transforms in batch, faction colour in
  `PerInstanceCustomData`. Placeholder meshes and a master material generated by a Python tool.
- **Control**: WASD/zoom camera; one order per unit (LMB select, RMB move/attack, Esc deselect) via
  transient Enhanced Input built in C++ (no input assets).
- **Battle**: game mode spawns two armies, resolves combat on a 2.0s timer, polls the win condition.
- **Lord ability**: Spacebar fires the selected unit's ability. Kai's Fire Blast and Samukai's
  Four-Armed Fury.

## v0.2 - Ranged combat

- Per-model ammo; ranged hit chance from `RangedAttack`, damage reuses the melee floor/AP model.
- Archers stand off inside their range and shoot, then charge to melee once out of ammo.
- Cosmetic projectile tracers arc from shooter to target.
- Demo ranged units: `NIN_SHINTARO` (Ninja) vs `SKU_ENGINEERS` (Skulkin).

## v0.3 - Morale and routing

- Pure morale resolver: casualty shock, under-strength penalty, safe recovery, and break/rally
  hysteresis so units do not flicker.
- Units break and flee from the nearest threat, then rally if they escape. `Morale == 99` is the
  immune flag (Skulkin, heroes) and never routs.
- Demo gains a breakable block (`NIN_SOLDIERS`) and a red routing marker.

## v0.4 - Charge impact

- First melee contact after advancing adds `ChargeBonus` to damage.
- The charge also delivers a morale shock to the struck unit, so a charge can break a wavering line
  (composes with v0.3). Re-arms when a unit disengages and re-advances.

## v0.5 - Spears and anti-large

- Unified `ResolveMelee` folding charge, spear anti-large bonus, and spear-braces-large-charge.
- "Large" is classified by `ModelScale >= 1.4` (cavalry, monsters, giants, vehicles).
- Demo gains the Ninja monster `NIN_SAMURAIX` for the Skulkin spears to brace against. Result: a
  charge/spear counter-triangle.

## v0.6 - Ability variety

- General magnitude parser (`verb=value%`) and an N-nearest chain-target selector.
- Abilities dispatch on verb and target: instant AoE, channelled AoE, chain damage, and heal.
- Each ninja hero is distinct: Kai/Cole burst AoE, Jay's Lightning Bolt chains. Zane's Ice Wall is a
  terrain effect and is honestly logged as not implemented.

## v0.7 - Buffs and debuffs

- Timed stat-modifier stack (flat + percent, expiry). Units expose effective attack, defence,
  damage, and speed, which flow through combat and movement.
- Buff/debuff ability verbs apply modifiers: `atk`, `def`, `speed`, `slow`, `buff`, `atkspeed`.
- Demo gains the Skulkin buffer `HRO_WYPLASH` (`def=+3` ally buff).

## v0.8 - Skulkin "Already Dead" revive _(integration)_

- Slain Skulkin models reassemble once, 20s later, at 50% HP, where they fell.
- The win condition counts reassembling models, so a unit with pending revives is not yet beaten.
- With their morale immunity, Skulkin are now a relentless horde. The battle still terminates
  (finite model-lives). Verified by trace, not a new test.

## v0.9 - Crowd control: freeze _(integration)_

- Freeze abilities (`freeze=Ns`) stun the target: it holds in place and cannot fight, move, or cast
  for the duration. Combat and target acquisition skip stunned units; a cyan marker flags them.
- Demo gains a guest freeze-caster, `LRD_ICEEMPEROR`, on the Ninja side. A strong counter to the
  Skulkin revive. Mind-control (`control=`) remains unimplemented.

## Roadmap

Ordered roughly by value, not commitment. The pure-combat-logic seam that made v0.2-v0.9 easy to
verify without a compiler is largely mined out, so most of these are more engine-coupled and
lower-confidence to build without the editor.

**Do first**
- **Compile and playtest v0.9 on Windows.** Nine unverified phases is a lot to debug at once. Watch
  the first-build items in `docs/TESTING.md` (target-settings enums, the Python material, the `Tier`
  import).

**Playability and feel** (turns the demo into a toy)
- Restart-battle key and auto-restart after a result (mostly pure C++).
- Health bars over units, a real win screen, hit/death feedback (some UMG/material assets).
- Sound cues.

**More combat and ability classes** (bigger engine systems)
- Terrain: Zane's Ice Wall and obstacles. Needs blocking geometry and steering-around, which cuts
  against the current flat-plane/straight-line movement.
- Mind-control (`control=full/partial`): temporary team switch of an enemy unit.
- Summon/raise (Serpentine, Greenbones) and other faction mechanics.
- Stealth and reveal.

**Content**
- Wire more of the 17 factions playable; a pre-battle army picker (UMG).

**Art**
- Replace placeholder minifig primitives with real geometry from the LDraw parts library.

## Design guardrails (do not cross)

- One unit, one order. No formations UI, facing, stances, or multi/box-select.
- Lords get exactly one extra button (Spacebar).
- All gameplay numbers come from the DataTables; the only constants in C++ live in
  `UNinjagoSettings`.
- No skeletal meshes.
- If a seven-year-old cannot hold a feature in his head, it does not belong here.
